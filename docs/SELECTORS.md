# BOSS 推荐页适配说明

默认 CSS 是初始候选，未通过真实账号的登录后页面验收。页面布局会因入口、账号和改版而不同。工具只在你手动确认的推荐列表中运行，不能自动判断该列表是否为个性化推荐。

## 如何校准

1. 正常打开工具浏览器，手动登录并进入推荐列表，暂不要输入 START。
2. 在浏览器开发者工具的 Elements 面板定位推荐列表的最外层容器。选择只包含当前推荐列表、在页面上唯一的 CSS。
3. 定位单个岗位卡片、卡片中的职位链接和字段。卡片链接必须是 `https://www.zhipin.com/job_detail/<ID>.html` 或对应相对路径；没有真实链接的卡片不会被工具猜测打开。
4. 把选择器写进 `config.local.json`（从完整示例复制，或使用部分覆盖），退出本次程序后带配置重新运行 `--limit 5`。
5. 核对导出表中岗位名称、薪资、公司与页面是否一致。核对 JD 属于同一个岗位，而非弹层、其他推荐或公司描述。

最小结构示例（不是实际平台页面）：

```json
{
  "selectors": {
    "feed_roots": ["#recommend-section .list"],
    "cards": [".job-card"],
    "link": ["a[href*='/job_detail/']"],
    "title": [".position-name"],
    "company": [".company-name"],
    "jd": [".job-description"]
  }
}
```

示例 CSS 仅说明格式。不要直接照抄未核实的选择器。`feed_roots` 不能设成 `body` 或整个页面，否则会把其他模块的岗位混入人工确认的范围。

## 解析规则

- 列表容器按 `feed_roots` 的数组顺序选择，第一个存在的可见候选必须唯一；同一候选命中多个可见容器直接停止。
- 卡片按 `cards` 顺序选择第一个有可见结果的候选，不合并所有候选，避免嵌套卡片重复。
- 字符串字段按候选顺序取第一个可见元素的 `innerText`；列表字段取第一组有可见文本的结果，去掉完全相同的标签。
- 候选从卡片/列表的**后代元素**中查找，不包括容器自身；若链接就是最外层卡片，请将 `cards` 定位到它的父级包装元素。
- 不读取 `display:none`、不可见/透明元素文本、JSON script、网络响应体或前端内部状态；不自动点击「展开」或登录后解锁入口。
- 「可见」指浏览器中已渲染的 DOM，允许位于当前视窗下方；不强行提取未渲染的虚拟列表内容。
- JD 只提取第一个匹配的可见正文元素。应让该 CSS 覆盖完整职位正文，不能把公司介绍当作职位正文。
- 岗位详情页不是沿着相似岗位继续爬；只访问已保存卡片的规范详情 URL，追踪查询参数会移除。
- 列表只会滚动已选容器的最近可滚动祖先，找不到时滚动文档。不会自动点击加载更多/下一页。

没有 CSS 能适配所有页面。遇到结构变化，先检查局部 DOM 并缩小范围；不要回退成全站链接扫描或寻找内部接口。

## 验收步骤

- 先 5 条，只采卡片，与页面逐条核对；记录字段缺失是否真实缺失。
- 用相同工作目录、不带 `--cards-only` 补 JD，检查来源链接及正文一致性。
- 把上限提高到 10 条，确认数据库总数为 10 且前 5 条不重复。
- Ctrl+C 后 `status` 和 `export` 均可运行；再继续处理剩余 `pending`。
- 不要在真实平台故意制造风控或反复触发验证。风控行为由本地合成页面测试验证。

提交适配修复时仅附脱敏的最小 HTML 结构，不上传 Cookie、账号截图、完整响应、浏览器资料、岗位数据库或真实 JD。
